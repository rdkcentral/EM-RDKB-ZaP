# Test Case 1: EasyMesh_MemoryCPU_Stability_Under_Traffic

## Objective

Verify that `onewifi_em_agent`, `onewifi_em_ctrl`, and `OneWifi` processes remain stable (no continuous increase in memory or CPU usage, no process restarts, no crashes) on the Controller and EM Agent 2 while continuous data traffic is generated by clients over a 24 hour period.

## Test Type

**Positive**

---

## Test Environment

| Component | Description |
|-----------|-------------|
| Controller | EasyMesh Controller |
| EM Agent 2 | EasyMesh Agent under memory/CPU monitoring |
| EM Agent (all other agents) | EasyMesh Agent1 and  EasyMesh Agent3 |
| Wi-Fi Client | At least 1 client per EM devices |
| Orchestrator | Test Orchestrator and telemetry collector |
| Network Topology | Hybrid topology with 1 Controller and 3 Extenders |

---

## Pre-Requisites

1. Controller and Extenders are onboarded successfully.
2. EasyMesh and IEEE 1905 services are running.
3. `rdkbcli` is available and accessible.
4. Ensure no core dump files exist under `/tmp`; if present, remove them before starting.
5. Verify the binary sizes of `OneWifi`, `onewifi_em_agent`, `onewifi_em_ctrl`, and `onewifi_em_cli`: `onewifi_em_cli` should be < 7 MB;
   `OneWifi`, `onewifi_em_agent`, and `onewifi_em_ctrl` should each be < 2 MB.

---

| Parameter | Value |
|-----------|-------|
| Processes Monitored | `onewifi_em_agent`, `onewifi_em_ctrl`, `OneWifi` |
| Memory Metrics | RSS, PSS, Swap (from `/proc/<pid>/smaps_rollup`) |
| CPU Metric | `top -bn2 -d 1 -p <pid>` (9th column) |
| Sampling Interval | Every 5 minutes |
| Test Duration | 24 hours |
| Backhaul Verification | `iw dev <backhaul interface> link` or `Device.WiFi.DataElements.Network.Device.{i}.BackhaulMediaType` |

---

## Test Environment

| Component | Description |
|-----------|-------------|
| Controller | EasyMesh Controller |
| EM Agent 2 | EasyMesh Agent under memory/CPU monitoring |
| EM Agent (all other agents) | EasyMesh Agent1 and  EasyMesh Agent3 |
| Wi-Fi Client | At least 1 client per EM devices |
| Orchestrator | Test Orchestrator and telemetry collector |
| Network Topology | Hybrid topology with 1 Controller and 3 Extenders |

---

## Pre-Requisites

1. Controller and Extenders are onboarded successfully.
2. EasyMesh and IEEE 1905 services are running.
3. `rdkbcli` is available and accessible.
4. Ensure no core dump files exist under `/tmp`; if present, remove them before starting.
5. Verify the binary sizes of `OneWifi`, `onewifi_em_agent`, `onewifi_em_ctrl`, and `onewifi_em_cli`: `onewifi_em_cli` should be < 7 MB;
   `OneWifi`, `onewifi_em_agent`, and `onewifi_em_ctrl` should each be < 2 MB.

---

## Test Configuration

| Parameter | Value |
|-----------|-------|
| Processes Monitored | `onewifi_em_agent`, `onewifi_em_ctrl`, `OneWifi` |
| Memory Metrics | RSS, PSS, Swap (from `/proc/<pid>/smaps_rollup`) |
| CPU Metric | `top -bn2 -d 1 -p <pid>` (9th column) |
| SSID Broadcast Verification | `iw dev <multi-link interface> info`; client side `sudo nmcli device wifi rescan` + `nmcli device wifi list` |
| Client Reconnection Verification | `iw dev <interface> station dump` |
| Iterations | 1000 times |
